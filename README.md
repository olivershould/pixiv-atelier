# Pixiv Atelier · 画序

在本机整理图片、标签、排期与作品数据的 Pixiv 投稿工作台。支持多个账号、历史投稿模板、本地识图、角色记忆、滚动预约和发布状态核实。

画序可以独立运行，不需要 ChatGPT、Codex、GPT API 或 agent-browser。**本仓库发布源码，不包含 Node/Python 二进制、本地模型、登录资料或作品数据。** 使用前需自行准备运行环境。它不是 Pixiv 官方产品；浏览器适配可能随站点变化而失效。

## 从源码启动

需要 **Node.js 22.13 或更新版本**。基础工作台没有第三方 Node 依赖，无需运行 `npm install`。Windows 上的浏览器接入另需 Google Chrome。

1. 下载或克隆仓库，进入项目目录。
2. 安装独立的 Node.js 22.13+ 并确保它在系统 PATH 中，然后双击 `Start.cmd` 或 `Start.vbs`。也可显式指定自己的 `node.exe`：

   ```powershell
   .\Start.ps1 -NodeExecutable 'C:\Program Files\nodejs\node.exe'
   ```

3. 启动器在后台运行服务，并打开 [本地工作台](http://127.0.0.1:4318)。

启动器依次选择项目内的 `.runtime/node/node.exe`、显式传入的 `-NodeExecutable`、PATH 中的独立系统 Node，最后检查 Program Files 下的标准 Node 安装路径，并检查版本；不会借用 Codex 的运行时。仓库不附带运行目录，也不会自动下载 Node。尚未安装符合条件的 Node 时，双击启动会提示缺少运行环境。

也可自行在终端启动，不使用 Windows 后台启动器：

```sh
node server/index.mjs
```

此时 Node 需已在当前终端的 PATH 中。默认进入隔离的演示空间，可体验示例队列；点击「使用我的账号」进入空白真实工作空间。演示不会向 Pixiv 投稿。

由启动器启动的服务使用 `Stop.ps1`、`Stop.cmd` 或 `Stop.vbs` 安全停止。正在投稿、同步或采集时会拒绝停止，请等待完成后重试。手动在终端启动的服务不属于启动器管理，需在任务结束后从该终端停止。

关闭网页不会停止后台服务；休眠、关机或服务退出时不会执行本地检查。准备项目内运行环境、迁移已有安装及备份方式见 [独立运行说明](docs/standalone.md)。`Install-Standalone.ps1` 是已有完整安装的迁移工具，**不是新电脑的一键下载安装器**。

## 登录 Pixiv

推荐每个账号使用独立的专用 Chrome：

1. 在真实工作空间的账号管理中添加账号资料，填写正确的 Pixiv 用户 ID。
2. 点击「使用专用 Chrome」或「打开登录窗口」，在该窗口登录对应账号。
3. 点击「确认已登录」，应用核对实际 Pixiv ID 与保存的 ID。
4. 确认连接后点击「转到后台」，保留登录状态并以无可见窗口的方式运行。
5. 检查作品、标签和排期，再用「开始预约」执行一轮；持续自动预约需另行开启该账号的投稿开关。

各账号登录资料独立，日常 Chrome 窗口不受影响。登录过期、验证码等仍需人工处理。兼容入口「连接现有 Chrome」也保留，该方式仍需浏览器远程调试授权。详见 [Chrome 登录与后台运行](docs/chrome-connection.md)。

## 功能

- **作品管理**：图片导入、多图排序、草稿、搜索、账号筛选、日历，以及批量删除确定未提交的本地记录。待预约、待补位、已预约、已发布分别展示，异常作品有独立入口。
- **一次选角色**：沿用当前账号历史投稿的英文标题、标签写法与顺序。常用标签池支持点击添加、搜索和手动维护；画面条件依据当前图片，不无条件复制旧标签。
- **可选本地识图与角色记忆**：上传后分析一次，可靠的单角色结果可填写标题和标签。未知、多图或多人时保留人工选择；明确保存的记忆可在账号间共用。
- **排期**：日期、时间分开选择，固定日本时间并显示北京时间；每个账号有默认时刻，新作品选择从现在起最近的下一次默认时刻。
- **滚动预约**：「开始预约」执行一轮；开启自动投稿后每 6 小时检查。最多同时准备 2 件作品，同账号依次确认预约，不同账号可同时提交。成功后只关闭应用本次创建的投稿页，失败或不确定时保留。
- **发布核实**：到点或预约消失不等于发布。应用匹配实际作品后才标记已发布；待核实的远端结果每 6 小时只读重查，关闭投稿或暂停队列仍可核实。现有「同步 Pixiv 状态」可立即核实，不会投稿。
- **数据统计**：按账号查看总浏览、总收藏、总点赞、粉丝数和每日增量，再查看作品、角色、标签及分时段增长排行。四项作品指标同时显示，点击列标题排序。

确认未上传的失败作品可重新预约；结果未知的作品先核实远端，不自动重复上传。标签、分级及创作方式仍需投稿前检查确认。

## 数据统计

作品与账号每 6 小时保存一次观测；作品发布后 **6 小时、12 小时、24 小时、7 天**另存固定节点记录。「更新数据」可立即请求采集，不触发投稿。

排行同时列出浏览、收藏、点赞和**收藏浏览比**，可查看截至目前或固定节点；角色和标签可按每作品平均比较。发布时间筛选提供全部作品、30 天内、90 天内、180 天内和一年内。作品表提供低清缩略图及 Pixiv 链接。

增长比较只纳入各账号启用统计后发布的新作品。「分时段增长」单独比较 0–6 小时、6–12 小时、12–24 小时及 24 小时–7 天的新增量和每小时新增。缺失节点不会用当前值补造，历史作品仍可参加普通累计排行。

账号总览不受作品排行的时间筛选影响；每日增量按北京时间划分，支持最近 7／30／90／365 天。首次记录不足、缺少前日基准或数据不可比时明确显示缺失或部分增量，真实负变化保留。完整公式、样本覆盖和采样窗口见 [数据统计口径](docs/analytics.md)。

## 安装本地识图（可选）

需要 Python 3.10 或更新版本；建议 **CPython 3.12 x64**、pip，以及约 467 MB 的模型和固定版本依赖。Windows 还需满足 ONNX Runtime 的运行库要求。未安装识图仍可管理草稿、手动选择角色和标签。

指定独立 Python 运行设置脚本：

```powershell
.\Setup-Tagger.ps1 -PythonPath 'C:\path\to\python.exe'
```

也可从终端执行：

```sh
python tagger/setup.py --install-deps --download-model --verify
```

设置脚本优先识别项目内 `.runtime/python/python.exe`，也支持显式路径。项目内的 Python、模型和依赖路径保存为相对项目根的配置，便于迁移；仓库本身不提供这些文件。安装完成后在「设置 → 检查本地识图」检查状态。详见 [识图安装说明](tagger/README.md) 和 [独立运行说明](docs/standalone.md)。

识图在本机 CPU 上执行，不通过 GPT 服务。模型概念不等于 Pixiv 标签；静态映射只提供未核实的候选，自动采用还需要账号历史、缓存或 Pixiv 查询来源。模型分数不是识别准确率。

## 支持范围与限制

目前支持插画和漫画，不支持小说、动图及已提交远端作品的修改／取消。应用按每账号最多 10 个远端预约、未来一周和 JST 整点／半点检查；实际权益与可用性以 Pixiv 返回为准。本地待补位队列可保存更多作品及更远的计划。

不支持的高级投稿选项会在上传前拦截。排期过期不会改成立即公开发布，网络超时也不会被当成确定未上传。具体字段见 [投稿字段与支持范围](docs/pixiv-fields.md)。

## 私人数据与备份

仓库不附带真实账号、登录会话、图片、投稿历史、统计数据或运行日志。使用后这些资料保存在本机：

| 位置 | 内容 |
| --- | --- |
| `.data/state.json`、`.data/uploads/` | 账号、作品、排期、执行记录和导入图片 |
| `.data/chrome-profiles/` | 每个账号的专用 Chrome 登录资料 |
| `.data/browser-ledger.json` | 提交幂等记录和发布核实依据 |
| `.data/tag-pools.json`、`.data/character-memory.json` | 标签历史、模板和角色参考 |
| `.data/analytics.sqlite` | 作品与账号观测、固定节点、采集进度 |
| `.data/models/`、`.data/tagger-config.json` | 识图模型与本机配置 |
| `.runtime/` | 自行准备的 Node、Python 和识图依赖 |

备份前安全停止服务及专用 Chrome，再复制整个安装目录；至少保留完整 `.data`。运行中的 SQLite 可能有 `-wal`、`-shm` 文件，不要只拷贝主库。界面的 JSON 导出不包含图片、登录资料和全部辅助数据，不能替代完整备份。当前没有完整备份导入界面。

专用 Chrome 资料包含登录状态，应视为私人资料。跨电脑迁移可能需要重新登录。不要将 `.data`、`.runtime`、本机配置、日志或私人验证材料提交到公开仓库。

应用仅监听 `127.0.0.1`，没有独立登录认证，不应直接暴露到公网。统计和状态同步只读取 Pixiv；真正投稿会发送所选图片及投稿资料。关闭应用无法撤销已经确认发送到 Pixiv 的预约。
