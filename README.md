# Pixiv Atelier · 画序

在本机整理图片、标签与排期的 Pixiv 投稿工作台。支持多个账号、历史投稿模板、本地识图、角色记忆、滚动预约和发布状态核对。

这是独立开发的应用，不是 Pixiv 官方产品。浏览器适配依赖 Pixiv 当前页面与接口，站点变化可能使部分功能暂时不可用。

## 快速开始

需要 **Node.js 22 或更新版本**。基础工作台没有第三方 Node 依赖，无需执行 `npm install`。

1. 下载或克隆此仓库，进入项目目录。
2. Windows 双击 `Start.cmd`，或在 PowerShell 运行 `./Start.ps1`。
3. 打开 <http://127.0.0.1:4318>。启动器会自动打开页面并在后台运行服务。

也可以在终端启动：

```sh
node server/index.mjs
```

默认进入独立的演示空间，其中包含示例账号与作品。可以在设置中推进演示时间，体验预约名额释放与自动补位；演示不会向 Pixiv 投稿。选择「使用我的账号」后进入空白的真实工作空间，两种空间的数据分别保存。

Windows 启动器运行的服务可用 `./Stop.ps1` 停止。关闭网页不会停止后台队列；电脑休眠、关机或服务退出期间不会执行预约检查。

## 连接现有 Chrome

1. 在 Chrome 中登录需要投稿的 Pixiv 账号，并保持该标签页打开。
2. 打开 `chrome://inspect/#remote-debugging`，启用远程调试。
3. 在应用的真实工作空间进入「账号管理 → 连接 Chrome」，允许 Chrome 的连接提示并选择检测到的账号。
4. 检查账号、作品内容、标签与预约时间后，将作品加入队列。
5. 在工作台点击「开始预约」执行一轮；需要持续运行时，为账号开启自动投稿。

应用复用现有 Chrome 登录状态，无需填写密码或复制 Cookie。连接期间的操作在后台进行，不主动将 Chrome 窗口切到前台。Chrome 或应用重启后可能需要再次允许连接；登录、人机验证及浏览器授权由用户处理。

内置连接目前默认发现 Windows Chrome 的本机调试端点。使用其他资料目录时可设置 `PIXIV_CHROME_USER_DATA_DIR`；具体流程及覆盖范围见 [Chrome 连接说明](docs/chrome-connection.md)。应用不需要安装 agent-browser 命令行工具。

## 主要功能

- **作品管理**：拖放或批量导入 PNG、JPEG、静态 GIF；多图排序、草稿编辑、搜索、账号筛选和批量删除尚未提交的记录。
- **清楚的投稿状态**：待预约、待补位、已预约、已发布分别展示；异常或结果不确定的作品有独立入口。
- **历史投稿模板**：同步自己的已发布作品后，一次选择角色即可填写英文标题和该账号惯用的标签组合，保留标签写法与顺序。各账号模板独立。
- **常用标签池**：点击添加、筛选、手动保存和移除常用标签；同步 Pixiv 后可沿用账号的标签习惯。
- **可选本地识图**：上传完成后分析图片，建议角色、分级和标签。单图单角色可靠识别时自动填写英文标题；不确定、多图或多人时留空，支持手动修正。
- **角色记忆**：确认角色后保存本机参考，同一图片可以复用名称；相似图片仅提供待确认候选。记忆可在账号间共用，演示与真实空间隔离。
- **排期与日历**：日期、时间分开选择，预约固定日本时间并显示北京时间。每个账号可设置默认投稿时间，新建作品选择从现在起最近的下一次默认时刻。
- **预约队列**：手动「开始预约」或开启每 6 小时一次的自动检查。核对远端名额和发布结果后，为待补位作品安排预约。
- **重新预约**：确认未上传的失败作品可点击「重新预约」，保留内容与排期重新入队；排期已过期时先调整时间。结果未知的作品必须先核对远端，避免重复投稿。

投稿前仍需检查并确认标签、分级及创作方式。历史画面标签不会无条件套用到新图片，模型分数也不代表识别准确率。内置静态词表只提供未核实的搜索候选；自动选标签需要当前账号历史、已核实缓存或 Pixiv 查询的支持。

## 安装本地识图（可选）

需要 **Python 3.10 或更新版本**、pip 和约 467 MB 的模型下载，识别在本机 CPU 上执行。

Windows 双击 `Setup-Tagger.cmd`，或运行：

```sh
python tagger/setup.py --install-deps --download-model --verify
```

安装完成后在应用「设置 → 检查本地识图」确认状态。未安装模型也可以管理草稿、手动选择角色和标签。安装文件、依赖和使用限制见 [识图安装说明](tagger/README.md)。

## 预约与使用限制

Pixiv 预约需要账号具有相应权益。应用按每账号最多 10 个远端预约、未来一周及 JST 整点／半点的规则检查；本地待补位队列可以保存更多作品及更远的计划。实际可用性以 Pixiv 返回为准。

到达计划时间或预约从列表消失，都不直接算作发布成功。应用核对可唯一匹配的实际作品后才更新状态；断线、身份变化、未知提交结果会暂停相关处理。过期而尚未提交的作品需要重新安排时间，不会自动改成立即公开发布。

目前支持插画和漫画。小说、动图，以及修改／取消已提交的远端作品不在本版实现范围。部分高级投稿选项也未接入，遇到不支持的内容会在上传前停止，详见 [字段与支持范围](docs/pixiv-fields.md)。

## 本机数据与备份

仓库只包含程序、通用映射和合成测试数据，不附带登录会话、账号资料、真实图片、投稿历史或运行日志。首次使用后创建的私人数据保存在本机：

| 位置 | 内容 |
| --- | --- |
| `.data/state.json` | 工作空间、账号、队列与执行记录 |
| `.data/uploads/` | 导入的图片 |
| `.data/character-memory.json` | 角色参考摘要与本机特征 |
| `.data/tag-pools.json` | 账号常用标签与历史模板来源 |
| `.data/browser-ledger.json` | 提交与发布核对记录 |
| `.data/models/`、`.data/tagger-config.json` | 模型与本机运行配置 |
| `.runtime/tagger/` | 本项目的 Python 依赖 |

先停止服务，再备份整个 `.data` 目录。界面中的 JSON 导出不包含图片和全部辅助数据，不是完整备份；当前没有完整恢复导入入口。私人目录、本机配置与日志不应上传到仓库。

图片分析默认在本机完成。连接 Pixiv 后，应用会读取账号与作品信息；执行投稿时会将所选作品和投稿资料发送到 Pixiv。应用仅监听 `127.0.0.1`，没有独立登录认证，不应直接映射到公网。
