# 沿用现有 Chrome 登录

1. 保持 Chrome 打开。在 `chrome://inspect/#remote-debugging` 开启远程调试；Chrome 弹出接入提示时选择允许。
2. 分别在需要使用的 Chrome 个人资料中打开 Pixiv，确认已登录。
3. 启动画序，进入真实工作空间 → 账号管理 → 连接 Chrome。
4. 选择检测到的 Pixiv 账号。已有同 ID 的本地账号会沿用，另一个账号会独立建立资料。绑定成功后，默认仅连接与同步，不提交作品。
5. 检查作品内容和未来排期，在作品详情使用「检查浏览器」。工作台「开始预约」会立即执行一轮；需要持续自动预约时，按账号点击「开启投稿」，之后每 6 小时检查一次。队列与账号暂停开关仍然有效。

Chrome 的授权针对调试连接。连接保持期间重复操作会复用同一会话；Chrome 重启、拒绝连接、会话参数改变或后台连接进程重启时，可能再次要求允许。程序不会自动替用户批准 Chrome 的提示。

若尚未允许连接，应用约 15 秒后提示等待授权，同时保留同一条待授权连接。之后在 Chrome 点击允许再重试即可；不会因为一次请求等待超时就撤销提示、反复建立新连接。超时的投稿操作不会在稍后授权时自动执行。

画序默认使用持续的后台连接：选择账号、读取状态、查询标签和操作投稿表单时，不激活 Chrome 窗口；新投稿页在后台创建。Chrome 可以保持原来的窗口、个人资料和登录状态。浏览器自己的调试授权或登录验证仍需手动处理。标签页被关闭或无法响应时会报告错误，不会通过抢到前台来恢复。

## 账号与数据

- 以 Pixiv 用户 ID 验证身份，不以 Google 账号名、Chrome 窗口标题或页面所浏览的作者推断登录者。
- 只检测 Pixiv 标签页。绑定保存标签页 ID；关闭它后必须重新绑定，不会自动跳到另一个账号。
- 每次同步通过该标签页的 Cookie 上下文重新读取登录身份。投稿前再次核验，登录改变立即停止该账号并关闭其投稿开关。
- 投稿使用新建的专用标签页，创建后核验身份再填表。用户原有标签页不会被导航到投稿页面。
- 多个 Chrome 个人资料均使用所属账号的后台页；先验证新页环境再导航。专用投稿页启用页面活跃仿真，使日期菜单在后台也能渲染，不激活 Chrome 窗口；原有用户标签页不启用此仿真。
- 不导出 Cookie、密码或 CSRF token。`.data/browser-ledger.json` 保存提交幂等记录，应与其他 `.data` 文件一起备份。
- 默认从 Windows Chrome 的 `DevToolsActivePort` 读取本机调试连接；使用非标准资料目录时可在 `.data/browser-config.json` 指定 `userDataDir`，或设置 `PIXIV_CHROME_USER_DATA_DIR`。旧版保存的 `session`、`executable` 保留，但后台驱动不再依赖会激活窗口的 CLI 标签页切换。

## 当前覆盖范围

基础适配包括插画／漫画、图片顺序、标题、说明、标签、AI 标记、年龄限制、全年龄性描写、公开范围、标签编辑权限、评论、珍藏册、原创，以及转换为 JST 的预约日期与时间。填写后会回读字段、标签、预览图数量及预约时间，不一致就停止。带空格的标签、系列、关联作品、使用工具、成人内容属性、问卷、自定义缩略图目前在上传前拦截，不会悄悄忽略。

日期与时间菜单分别等待可见选项，只打开、选择一次，并等待页面回读确认。超时会说明失败的是日期还是时间以及目标值、当前值，不将菜单未渲染误报为 Pixiv 不提供该时段。

远端快照读取 Pixiv 自身作品管理接口的完整 `reservedWorks`，包含浏览器手动建立的预约，保守合计插画和小说预约数。预约 ID 与发布时间来自远端，时区缺失的 Pixiv 日期按 JST 解析；无法解析的日期不会当作预约已确认。

页面结构变化、身份不一致或不能确定提交结果时，应用会停止后续操作，并保留需要核对的记录。

## 不确定结果与发布确认

最终点击前保存幂等记录；点击后无法得到唯一匹配的新增远端预约时，作品进入待核对，不会自动重新上传。刷新或重启也不会清除这项保护。

预约到点或从列表消失都不等于已经发布。新预约提交前保存完整的已发布作品 ID 基线；预约到点且从完整预约列表消失后，自动检查基线之后出现的作品。只有作者、标题（含无题）、图片数量、插画／漫画类型和发布时间所在分钟均匹配，且不存在其他候选或提交记录冲突时，才保存最终作品 ID、标记已发布，并在本轮继续补位。

仍在 Pixiv 预约列表中的旧记录可以补齐基线；升级前已经消失且没有基线的记录保留人工核对。候选超过 100 件、读取失败、信息不完整或结果不唯一时保留名额，不猜测发布，也不重复上传。可在作品详情使用「核对远端结果」确认实际预约或作品链接。

发生断线、换号、标签页关闭或身份验证失败时，重新检测、绑定并同步。持续投稿未开启时不会自动执行。旧排期已经过期的作品保留待处理状态，需要重新设置未来时间。

「开始预约」仅授权当次已加入队列的作品执行一轮，不改变各账号持续投稿开关，不恢复已暂停队列。多次点击复用正在执行的同一轮；界面显示实际预约、确认发布、失败及待核对数量。每轮完成后将下一次自动检查设为 6 小时后，期限保存在本机，重启不会清除。运行中每 3 秒读取的只是本地进度，不会因此请求 Pixiv。

暂时网络超时不会关闭自动开关；本轮不使用失效快照提交，下个六小时轮次可以重新核对。身份改变、登录失效或绑定标签消失才关闭对应开关。执行中暂停会停止尚未点击提交的作品，已经发送的请求仍核验结果；不会通过打断响应来假装未提交。

账号头像在同步登录身份后从 Pixiv 账号资料读取，经过本机图片代理显示；失败时保留原头像或首字母。预约日历每条排期显示账号名称、头像、稳定区分色和状态。

## 自动识图、标签和默认排期

工作台右上角的「同步 Pixiv 状态」会核对所有已连接账号的登录状态、Premium、预约列表和占用名额，并更新能确认的本地作品状态。已暂停队列或关闭投稿的账号也可同步；未绑定的账号会列为未连接。页面显示最近同步时间及各账号结果，一处失败不影响其他账号的核对。同步只读取 Pixiv 状态，不触发投稿或自动补位。演示空间不使用真实同步。

预约消失或到达预定时间本身不能证明已经发布；无法确定的作品仍显示待核对，可在作品详情使用「核对远端结果」确认。

上传结束后自动识图一次；单图单角色填英文名，多图、多角色或识别不确定时标题留空。同时自动填写符合画面的标签，最多 10 个，顺序为游戏作品、R-18（R-18G 作品使用 R-18G）、角色、画面内容。AI 默认开启，分级自动建议，所有建议可修改。识图期间的手动修改及已保存的标题、分级、标签会保留；图片或账号变化后，过期结果不会覆盖当前草稿。批量导入也使用相同的自动填写流程。

全站标签通过已绑定账号的 Chrome 搜索，只发送识图关键词，不发送图片。自动候选要求关键词准确匹配，优先相关常用标签，并参考已保存的账号历史；轻量同步最多读取最近 60 件，完整历史可分批读取。历史中的无关标签不会加入当前图片；历史读取失败时继续使用可用来源并显示实际状态。可输入任意词搜索补充，标签仍需检查确认后才入队。所有读取沿用后台连接。

当前 WD 模型角色覆盖有限；不会以文件名、手填标题或历史作品名称冒充视觉识别。低置信度内容保留供检查，不自动填入标签。公开版本的通用静态映射只提供未核实候选，自动标签需要当前账号历史、已核实缓存或实时查询支持。

预约日期/时间分开，固定 JST，并显示北京时间。新建默认选择从现在起最近的一次账号默认投稿时间：当天尚未到点则选当天，已到或已过则选次日，均按日本时间判断；账号设置中的默认时间独立保存。工作台显示时区不改变投稿时区。

新账号的默认投稿时间为日本时间 09:00，可在账号设置修改。确认未上传且没有远端关联的失败作品，列表、卡片或详情会提供「重新预约」；有效排期保留并重新进入待补位，缺失或已过期则先打开排期设置。重新入队不会直接启动其他作品，可按既有自动规则处理或手动点击「开始预约」。

若在 Pixiv 手动改期，应用会标记时间不一致。在作品详情的「核对远端结果」选择已关联的预约，勾选「采用 Pixiv 当前排期更新本地记录」，即可仅更新本地时间，不重新上传。
